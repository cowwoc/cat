## Plugin Development

When editing CAT plugin files, always edit the source files in `${workPath}/plugin/`, NOT the cached installation in
`${CAT_PLUGIN_ROOT}`.

The cache is a read-only copy that gets overwritten on plugin updates.

**Binary Launcher Locations:** Compiled jlink binary launchers (e.g., `get-output`, `work-prepare`) are
generated by the jlink build process and live under `${CAT_PLUGIN_DATA}/client/bin/`. The workspace `client/`
directory contains only Java source code (`src/main/java/`) — there are no compiled binaries in
`${workPath}/client/bin/`.

**Worktree Path Handling:** When working in a worktree (e.g., `${workPath}`), use relative paths like
`plugin/skills/common/` instead of absolute paths like `${workPath}/plugin/`. Absolute paths to the main workspace
bypass worktree isolation and modify the wrong workspace.

**All code changes require a worktree:** Any modification to `plugin/` or `client/` source files — including
user-requested "direct fix" changes — must be made inside an issue worktree, never directly in the main workspace.
When a user asks for a "direct fix", create a minimal single-commit worktree branch rather than editing the main
workspace directly. Worktree-isolation hooks block edits to the main workspace when an active worktree exists.
